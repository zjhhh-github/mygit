# 散件发货回填脚本说明

## 1. 脚本作用

`read_feishu_bitable.py` 用于读取飞书多维表格数据，并按“散件名称 -> 编号/金额”的映射关系，自动回填目标表中的以下字段：

- `散件编号(最终)`
- `散件总金额`

同时，脚本会基于回填结果自动新增“拆分行”（并写入拆分标记），用于后续发货处理。每一条拆分新增行还会
写入 `发货仓`（普通文本字段，值来自散件信息表对应编号的真实发货仓，详见 3.3.1 节）。

如果你只需要“读表 -> 计算散件总金额 -> 写入散件总金额”，可使用独立脚本：

- `read_feishu_bitable_amount_only.py`
- 该脚本仅写回 `散件总金额`，不会写 `散件编号(最终)`，也不会做拆分新增。

## 3. 处理规则（核心）

### 3.1 匹配与金额计算

1. 按“完全匹配”查找映射表中的散件名称（不做模糊匹配）。
2. 数量字段名由散件名称推导：把最后一个 `【...】` 替换为 `【数量】`，例如：
   - `牛津树 绘本（套装）【300元】` -> `牛津树 绘本（套装）【数量】`
3. 数量取值规则按来源字段区分：
   - `散件名称`：必须有可解析的数量值；数量字段为空/缺失/非法时，该子项跳过。
   - `手动特殊处理`：若存在可解析数量则按该数量；数量字段为空/缺失时默认按 `1`；非法值仍跳过。
4. 金额优先读取映射表 `金额(对外展示)`（或金额/价格），若解析不到数字则回退从名称中的 `【xx元】` 提取。
5. 单个散件命中多条映射时：
   - 编号会合并去重后继续处理
   - 金额会按所有有效单价累计
6. 同时读取映射表 `发货仓`（公式字段，结果为“深圳云仓/王师傅下单/非快递订单/呼市云仓”之一），
   记录每个散件对应的发货仓类别，用于 3.3 节的拆分分组。

### 3.2 编号回填规则

- 每个匹配到的编号都按 `编号*数量` 格式输出。
- 多个编号用英文逗号拼接后写入 `散件编号(最终)`。
- 部分“展示编号”会先按编号替换表翻译成真实要写入飞书的编号，再拼上 `*数量`：
  - 展示编号 `读写工具包-25本装-[1/6]` -> 写入飞书时替换为 `MJKD3P0136,MJKD3P3772,MJKD3P73108`
    三个真实编号（各自带上相同的数量后缀，用逗号拼接）
  - 替换表维护在脚本内的 `CODE_DISPLAY_TO_REAL_CODES`，后续如果还有类似“一个展示编号
    对应多个真实编号”的情况，直接在这个字典里加一行即可，不需要改其他代码

### 3.3 拆分新增规则

脚本会在更新原记录后新增拆分行，且会跳过已标记“拆分”的记录，避免重复执行导致指数级新增。

拆分规则按以下优先级依次判断（从上到下，命中即停止，不再往下判断）：

1. **强制单独拆分项**：始终独立成一行，编号合并在一起、不按编号逐条拆。
2. **映射表里“同名重复”的散件**：按编号逐条拆分（一个编号一行），金额按拆分条数均摊。
   例如“读写工具包-套装【900元】”在映射表里对应 6 个不同编号（6 本书各一个编号），
   会先按编号拆成 6 行，这条规则**必须保留**，不能被下面的“展开单件”规则跳过。
3. **不属于第 1/2 条、但仍需要展开成单件多行的散件**（见下方“展开单件”名单）：
   独立成一行，不与其他不同散件合并，避免合并后名称对不上导致下面的展开规则失效。
4. **其他散件**：默认合并，但会**再按“发货仓”类别分组**：不同发货仓的散件不会合并到
   同一条拆分行，每个发货仓类别单独生成一条拆分行（金额按各自散件累加，互不混算）。

无论落在第 1/2/3 哪一条规则，只要该散件属于“展开单件”名单，都会再叠加一层判断：
**是否需要把 `*N` 展开成 N 条 `*1`**（金额同步均摊）。展开单件名单：

`西游记绘本-套装【100元】`、`小猪佩奇-L系列-台词书-套装【150元】`、
`动物街-L系列-台词书-套装【100元】`、`小四件(蓝)【200元】`、`小四件(粉)【200元】`、
`牛津树-L系列-绘本-套装【300元】`、`蛋壳阅读练习册-套装(1-12)【350元】`、`读写工具包-套装【900元】`

举例：“读写工具包-套装【900元】”买了 2 套，会先按第 2 条拆成 6 行（每个编号一行，
每行 `*2`），再对每一行按展开规则拆成 2 行 `*1`，最终共 12 行（6 个编号 × 2 套）。

#### 3.3.1 发货仓分组规则说明

- 映射表（散件信息表）的 `发货仓` 仍然是**公式字段**：根据同表内“编号(对外展示)”内容，
  用 `IFS(CONTAINTEXT(...))` 自动判定属于「深圳云仓 / 王师傅下单 / 非快递订单 / 呼市云仓」，
  作为“这个编号真实属于哪个仓”的唯一数据来源，脚本只读取它，不修改它。
- 目标表（散件发货客户自填表）的 `发货仓` 原来也是公式字段，**现已改为普通文本字段**
  （旧公式字段改名保留为 `发货仓旧`，可在飞书里对照查看），改为由脚本按下面的规则显式写入：
  - 每条**拆分新增行**都会写入 `发货仓`，值取自散件信息表里该行编号对应的真实发货仓；
  - 原始记录本身（更新 `散件编号(最终)`/`散件总金额` 的那一行）**不会**写 `发货仓`，
    因为原始记录往往合并了多个散件、可能跨多个仓，写单一值容易误导，实际发货以拆分行为准。
- **按编号逐条拆分**（3.3 节第 2 条“同名重复”规则）时，每条编号使用**自己映射行的真实发货仓**，
  不会因为同名散件其他编号是别的仓而被覆盖。例如“读写工具包-套装”6 个编号里，
  有的实际是“深圳云仓”、有的是“呼市云仓”，拆分后每一行都会写入各自真实的仓，
  按数量展开成多行时（`*N` -> N 条 `*1`）也是同一个编号复制出来的，天然带着同一个正确的仓。
- **默认合并**（3.3 节第 4 条）时，若多个不同散件分属不同发货仓，脚本会把它们拆到不同的新增行里，
  每条新增行只包含同一个发货仓的编号，`发货仓` 字段写入该仓类别，不会出现混仓的情况。
- 只有**强制单独拆分项**（3.3 节第 1 条，业务要求必须合并成一行、不能按编号拆开）才会在
  多条映射命中且发货仓不一致时，退化为按第一条非空值处理，并在日志中打印警告，
  提示需要人工核对映射表数据（这是唯一无法做到“每条数据都用真实发货仓”的场景，
  因为这类散件本身就要求不能拆成多行）。

### 3.4 拆分标记字段

- 默认使用字段名：`文本5`
- 若字段名有空格差异（如 `文本 5`），脚本会尝试自动识别
- 新增拆分行时，会把该字段写为：`拆分`

### 3.5 拆分行的“散件名称”“手动特殊处理”列也会一起拆开

拆分新增行会同时写入以下“名称”信息：

- `散件名称(脚本)`：始终是这条拆分行对应的散件名称原文（不管来源是“散件名称”列还是
  “手动特殊处理”列），方便直接核对这一行具体是哪个散件。
- `散件名称`（原字段，多选列）：**只保留这条拆分行涉及的选项**，不是这条拆分行涉及的
  散件会被去掉。例如原记录“散件名称”选了 A、B、C 三个散件，拆分成 3 行后，
  A 所在的拆分行“散件名称”只显示 A，不会再显示 B、C。
  - 只使用原记录“散件名称”里**已经勾选的选项**做匹配，不会新增新的多选选项。
  - 如果这条拆分行的散件其实来自“手动特殊处理”列（不是从“散件名称”里选的），
    那么这条拆分行的“散件名称”会写成空（因为它本来就不属于“散件名称”这一列）。
- `手动特殊处理`（原字段，多选列）：规则与“散件名称”完全对称，**只保留这条拆分行
  涉及的选项**，也只使用原记录里已经勾选的选项做匹配，不会新增新的多选选项。
  - 如果这条拆分行的散件其实来自“散件名称”列（不是从“手动特殊处理”里选的），
    那么这条拆分行的“手动特殊处理”会写成空。
  - 也就是说：一条拆分行的散件，最终只会出现在它真正来源的那一列
    （“散件名称”或“手动特殊处理”）里，另一列会是空，两列不会互相串号。

## 4. 运行前准备

1. 在飞书开放平台获取应用凭证：
   - `App ID`
   - `App Secret`
2. 确认应用具备多维表格读写权限（读取记录、更新记录、新增记录）。
3. 确认目标表至少包含以下字段：
   - `散件名称`
   - `散件编号(最终)`
   - `散件总金额`
   - 拆分标记字段（默认 `文本5`）
4. 确认映射表至少包含：
   - 名称字段（如 `散件名称`/`物品名称`/`商品名称`/`名称`）
   - `编号(对外展示)`
   - 金额字段（建议 `金额(对外展示)`）
   - `发货仓`（公式字段，用于按发货仓分组拆分，映射表和目标表中都已存在，无需新建）

## 8. 常见问题

### 8.1 执行失败：`--page-size 必须在 1~500 之间`

将 `--page-size` 调整到合法范围内（建议 100）。

### 8.2 报“读取多维表格失败”或“获取 tenant_access_token 失败”

优先检查：

1. `app-id` / `app-secret` 是否正确
2. 飞书应用权限是否开通
3. App 是否有目标多维表读写权限

### 8.3 出现大量“映射表散件名称未找到完全匹配项”

说明目标表散件名称与映射表名称存在文本不一致。该脚本是“完全匹配”策略，需先清洗名称数据再执行。

## 9. 最小验证步骤（推荐）

1. 先执行 `--dry-run --print-debug`，确认：
   - `散件编号(最终)` 格式正确（`编号*数量`）
   - `散件总金额` 符合预期
   - 拆分预览条数和内容合理
   - `[拆分预览]` 日志末尾的 `发货仓(预计)=...`：同一条原始记录里，如果散件分属不同发货仓，
     应该拆成多条预览行，且每条只对应一个发货仓类别
2. 去掉 `--dry-run` 正式执行。
3. 回到飞书表格核验：
   - 原记录是否已回填两个字段
   - 是否新增了拆分行，且不同发货仓的散件是否已拆到不同行
   - 新增行的 `发货仓`（公式字段）是否显示了正确、单一的仓类别
   - 新增行是否写入拆分标记（默认 `文本5=拆分`）
