# 导入控制台 —— 使用文档

## 结论

「导入控制台」是一个 **Windows 桌面 GUI 工具**（Tkinter 实现，已用 PyInstaller 打包成 `导入控制台.exe`），
把公司日常需要手工跑的 **6 类数据导入/同步任务** 集中到一个窗口里管理：

| Tab 页签 | 作用一句话 |
|---|---|
| 增量导入 | Excel 意向通讯录 → 查重清洗 → 增量导入 Supabase |
| 内部备注导入 | 微信 `contact.db` 备注 → 写入 `internal_notes` 表 |
| 定时拷贝 | 按计划把 `contact.db` 等文件从网络路径拷到本地 |
| 飞书全量同步 | 意向学员绑定关系 → 全量重建飞书多维表格 |
| 用户上传 | 飞书多维表格账号密码 → 批量导入秒哒（Supabase）用户 |
| 扩展功能 | 无需重新打包 exe，即可挂载任意外置 Python 脚本作为插件 |

日常最常用的操作只有两步：**双击 `导入控制台.exe` → 在对应 Tab 点「立即运行 / 立即执行」**。
定时任务（每个 Tab 都支持）配置好后可以一直挂在后台自动跑。

## 二、运行方式

### 方式一（推荐，日常使用）：直接运行 exe

1. 双击 `导入控制台.exe`
2. 首次运行不需要安装 Python、不需要装任何依赖
3. 出现窗口后即可按下方各 Tab 说明操作

### 方式二（改代码调试用）：用 Python 直接跑源码

前提：本机已装 Python 3.10+，并已安装依赖（`requests`、`pandas`、`tqdm` 等，与 `增量导入.py` 顶部 `import` 一致）。

```powershell
cd D:\git\mygit\小工具\导入控制台
python .\导入控制台.py
```

> 依赖说明：`导入控制台.py` 需要同目录下的 `task_runner.py`（全局任务队列）和 `custom_plugins.py`（扩展插件支持）。
> 这两个文件已随目录一起提供；若缺失可从
> `数据结构处理/意向学员绑定关系查询系统/` 复制同名文件到本目录。

### 命令行 / 无界面模式（仅增量导入 + 内部备注）

```powershell
cd D:\git\mygit\小工具\导入控制台

# 只跑一次增量导入流水线，不弹 GUI
python .\导入控制台.py --no-gui

# 只跑一次内部备注导入（导出+上传），不弹 GUI
python .\导入控制台.py --no-gui --note
```

## 三、窗口总览

打开后窗口从上到下分为三部分：

1. **顶部：全局任务队列状态栏**——显示当前排队中/执行中的任务数量。
   多个 Tab 的「立即运行」如果都勾选了「加入全局队列」，会在这里排队顺序执行，避免互相冲突。
2. **中部：功能 Tab 页签**——见下方逐个说明。
3. **底部：日志区**——所有 Tab 的操作日志都会汇总打印在这里，排查问题优先看这里的报错信息。

## 四、Tab 详细说明

### Tab1：增量导入

**用途**：把「意向专用通讯录导出」Excel 里的新学员，经查重清洗后增量导入 Supabase。

**界面字段**：

| 字段 | 说明 |
|---|---|
| 触发间隔（分钟） | 定时自动执行的间隔，默认 15 分钟 |
| 首次触发时间（HH:MM） | 留空 = 启动后等一个间隔才第一次执行；填了就等到指定时刻才第一次执行 |
| 输出目录（CSV/JSON） | 每次运行生成的查重报告 CSV/JSON 存放位置 |
| 跳过已报名/有绑定学员 | 勾选后，意向学员查询系统中「已报名」或「有绑定」的学员不会被导入 |

**contact.db 同步区**（同一 Tab 内，独立小功能）：

| 字段 | 说明 |
|---|---|
| 来源根目录 | 网络备份根目录，默认 `X:\chatlog_backup` |
| 目录前缀（多个用 `;`） | 只在以这些前缀开头的备份目录里找 `contact.db`，默认 `wxid_42272spv9uq522_6ded` |
| 目标路径（多个用 `;`） | `contact.db` 拷贝到本地的落地路径，默认 `桌面\contact.db` |

**按钮**：

- `应用间隔` / `应用并保存`：保存对应字段到配置文件
- `启动定时` / `停止定时`：开启/关闭自动循环执行
- `立即运行一次`：手动触发一次完整流水线（Excel → 清洗 → 导入）
- `立即同步`：仅同步 `contact.db` 文件，不跑导入流水线

**涉及配置文件**：`tab1_console_config.json`（首次触发时间、目录前缀）；`增量导入.py` 顶部 `CONFIG` 字典（Supabase 地址、Excel 目录、批次大小等硬编码默认值，可用 `config.local.json` 局部覆盖 `OUTPUT_DIR`）。

**验证方式**：
1. 点「立即运行一次」
2. 底部日志应看到「读取 Excel → 查重 → 分批调用接口 → 汇总」的完整日志
3. 「输出目录」下应新增一份带时间戳的 CSV 报告

### Tab2：内部备注导入

**用途**：把微信 `contact.db` 里符合「¿¿¿011880-姓名」格式的备注，导入 `internal_notes` 表。

**界面字段**：

| 字段 | 说明 |
|---|---|
| 外置脚本路径 | 实际执行逻辑所在的 `.py` 文件，默认指向 `内部备注导入.py`。**改这个脚本不需要重新打包 exe，改完直接生效** |
| contact.db 路径 | 要读取的本地微信通讯录数据库文件 |
| 导出 JSON 路径 | 生成的中间 JSON 文件位置 |
| 上传模式 | `增量同步（推荐）`：按 `internal_note` 去重的 PostgREST 方式；`Edge Function`：走 `import-internal-notes` 云函数 |
| 自动触发 | 勾选后，Tab1 增量导入跑完，延迟 N 秒（默认 60）自动接着跑一次内部备注导入 |

**按钮**：

- `立即运行（导出并上传）`：导出 JSON 并上传
- `仅导出 JSON（不上传）`：只生成本地 JSON，方便先人工核对
- `保存配置`：把上方字段落盘
- `加入全局队列`：未勾选时若已有内部备注任务在跑会跳过本次；勾选后会排队等前面跑完，不丢失触发

**筛选规则**（写在 `内部备注导入.py` 里，改脚本即可调整）：
备注必须是 `¿¿¿６位数字-任意文字` 或 `¡¡¡６位数字-任意文字` 格式，且尾段不能是「空」或「删除」。

**验证方式**：
1. 先点「仅导出 JSON（不上传）」，检查生成的 JSON 内容是否符合预期
2. 确认无误后点「立即运行（导出并上传）」
3. 日志中应看到每批上传的成功/跳过/失败统计

### Tab3：定时拷贝

**用途**：管理多个「定时文件拷贝任务」，例如把网络路径上最新的 `contact.db` 定期同步到本地。

**任务列表**（Treeview 表格）列：任务名 / 来源路径 / 目标路径 / 间隔(分钟) / 首次触发(HH:MM) / 状态 / 上次运行 / 上次结果。

**新增/编辑任务对话框字段**：

| 字段 | 说明 |
|---|---|
| 任务名 | 自定义名称，仅用于展示 |
| 来源类型 | `固定路径（文件）`：拷贝指定的单个文件；`contact.db 动态查找`：在「来源根目录」下按前缀自动定位最新备份目录里的 `contact.db` |
| 来源路径 / 网络根目录 | 根据来源类型二选一填写 |
| 动态前缀（多个用 `;`） | 仅动态查找模式生效，例如 `wxid_a_6ded;wxid_b_6ded` |
| 目标路径（多个用 `;`） | 支持一次拷到多个目标位置 |
| 间隔（分钟） | 定时检查执行的间隔 |
| 首次触发时间（HH:MM） | 留空按间隔；填了则等到指定时刻才首次执行 |
| 启用状态 | 关闭后该任务不会被调度器执行，但保留在列表中 |

**按钮**：`新增任务` / `编辑任务` / `删除任务` / `启用/禁用` / `立即运行`（不受间隔限制，立刻执行一次）/ `刷新列表`。

**拷贝安全机制**：文件拷贝前会「等待文件稳定（连续多次检测大小/修改时间不变）→ 复制 → 大小校验」，避免拷到还在写入中的半截文件。

**首次启动预置**：程序会自动预置一条名为「contact.db 同步」的任务（若列表为空），来源为 Tab1 里配置的网络根目录，间隔 30 分钟。

**验证方式**：
1. 新增或选中一条任务，点「立即运行」
2. 查看「上次运行」「上次结果」两列是否更新为成功
3. 检查目标路径下文件的修改时间是否变为最新

### Tab4：飞书全量同步

**用途**：把「意向学员绑定关系」数据全量重建到飞书多维表格（先清空表内已有记录，再重新写入全量数据）。

⚠️ **风险提示**：真实执行（关闭 Dry Run）会 **清空飞书表内所有记录后重新导入**，不会删表/删字段/删视图，但会导致同步期间表内数据短暂为空。建议先用 Dry Run 试跑确认统计结果正常。

**界面字段**：

| 字段 | 说明 |
|---|---|
| 同步脚本路径 | 默认 `.\意向学员关系导入到飞书多维表格.py`，改脚本不需要重新打包 exe |
| 定时间隔（分钟） | 自动执行间隔，默认 60 |
| 首次触发时间（HH:MM） | 同其它 Tab 规则 |
| 执行模式：Dry Run | 勾选（默认建议开启）时只统计不清空、不导入；确认无误后取消勾选再正式执行 |

**按钮**：`保存配置` / `立即执行一次` / `启动定时` / `停止定时` / `打开字段映射配置`（用系统默认程序打开 `field_mapping.json`，方便直接编辑）。

**字段映射**（`field_mapping.json`，与脚本同目录）：

```json
{
  "student_id_field": "意向学员总微信号",
  "fields": [
    { "feishu": "意向学员总微信号", "source": "student.意向学员微信号" },
    { "feishu": "推荐人总微信号", "source": "source.来源微信号" },
    { "feishu": "绑定日期", "source": "source.绑定日期", "type_hint": "date" },
    { "feishu": "解绑日期", "source": "source.解绑日期", "type_hint": "date" },
    { "feishu": "绑定状态", "source": "source.绑定状态" }
  ]
}
```
`feishu` = 飞书表里的字段名，`source` = 数据来源字段（`student.xxx` 取学员信息，`source.xxx` 取绑定关系信息）。文件不存在时点「打开字段映射配置」会自动按脚本内置默认值生成一份。修改后下次同步立即生效，不需要重启。

**验证方式**：
1. 保持 Dry Run 勾选，点「立即执行一次」
2. 日志里应看到读取到的学员/绑定关系条数统计，且明确写着「Dry Run，未真正清空/导入」
3. 确认统计数字符合预期后，取消勾选 Dry Run 再执行一次
4. 打开飞书多维表格，核对记录数量与最新数据是否一致

### Tab5：用户上传

**用途**：从飞书多维表格读取「编号 / 意向通讯录密码 / 合伙宝妈总微信号」，生成本地 `上传用户结构.json`，再按 200 条/批调用秒哒（Supabase）`import-users` 接口批量建/更新普通用户账号。

**字段映射（固定，写在脚本里）**：

| 飞书字段 | 上传字段 |
|---|---|
| 编号 | 账号 |
| 意向通讯录密码 | 密码 |
| 合伙宝妈总微信号 | 微信号 |
| （固定值） | 角色 = "普通用户" |

**界面字段**：

| 字段 | 说明 |
|---|---|
| 同步脚本路径 | 默认指向 `上传用户结构.py` |
| 飞书视图 ID | 只读取该视图内的行；留空则读整张表；默认 `vew7GtEotv` |
| 执行模式 | `full`：拉取飞书 + 写 JSON + 上传（默认）；`json_only`：只生成本地 JSON 不上传；`upload_only`：跳过飞书拉取，只用现有 JSON 上传 |
| Dry Run | 勾选时只打印将要上传的批次数量，不真正发请求；建议首次务必勾选确认 |
| 定时间隔（分钟） / 首次触发时间 | 同其它 Tab 规则 |

**密码增量更新机制**：本地会缓存 `upload_password_cache.json`（账号 → 上次成功上传的密码）。同一账号密码没变时不会重复更新，密码变了才会覆盖。

**按钮**：`保存配置` / `立即执行一次` / `启动定时` / `停止定时`。

**独立运行方式（不经过 GUI）**：

```powershell
cd D:\git\mygit\小工具\导入控制台

# 全流程：拉取飞书 → 写 JSON → 上传秒哒（默认）
python .\上传用户结构.py

# 只生成 JSON，不上传
python .\上传用户结构.py --no-upload

# 只用本地已有 JSON 上传，不重新拉飞书
python .\上传用户结构.py --upload-only

# 拉取 + 写 JSON + 干跑上传（只打印将要上传的条数，不真发请求）
python .\上传用户结构.py --dry-run
```

**验证方式**：
1. 先保持 Dry Run 勾选，点「立即执行一次」
2. 日志中应看到「共 N 条，将分 M 批上传」等统计，且不会真的调用秒哒接口
3. 确认数量正常后取消 Dry Run 再执行一次
4. 检查 `上传用户结构.json` 内容，以及秒哒后台用户列表是否新增/更新成功

### Tab6：扩展功能（自定义插件）

**用途**：不用改 `导入控制台.py` 源码、不用重新打包 exe，就能挂载任意外置 Python 脚本作为一个新功能卡片。

**插件脚本约定**（写一个普通 `.py` 文件即可）：

```python
def run(log, **params) -> bool:
    """log 是控制台注入的日志对象，可直接 log.info(...) / log.error(...)。
    params 来自插件配置里的「参数 JSON」，作为关键字参数传入。
    返回 True/False 表示本次执行成功/失败；不写 return 视为成功。
    """
    log.info("hello")
    return True
```

**GUI 操作**：

- `+ 新增功能`：填「功能名称」「脚本路径」「入口函数（默认 run）」「参数（JSON 对象）」「是否启用」
- 每个插件显示为一张卡片，卡片上有「立即执行」按钮，默认进全局任务队列，不会与其它正在跑的任务冲突
- `刷新配置` / `打开配置文件`：刷新界面显示 / 直接打开 `custom_plugins.json` 手工编辑

**配置文件** `custom_plugins.json` 结构：

```json
{
  "queue_enabled": true,
  "plugins": [
    {
      "id": "abc12345",
      "name": "示例：清理临时文件",
      "script": "./示例插件.py",
      "entry": "run",
      "params": { "input_file": "C:/data.json" },
      "enabled": true,
      "auto_trigger": { "enabled": false, "interval_min": 60, "start_time": "" }
    }
  ]
}
```

**验证方式**：新增一个插件后，点卡片上的「立即执行」，观察底部日志是否打印 `[扩展功能][插件名] 开始执行` → `执行结束 → 成功/失败`。

## 五、独立脚本：export_students_flat_to_feishu.py

这是一个**不挂在任何 Tab 上**的独立脚本，用于把 `export-students-flat` 接口的导出数据同步到飞书多维表格（先清空指定表再全量写入，`--clear-existing` 时）。需要手动在命令行运行：

```powershell
cd D:\git\mygit\小工具\导入控制台

# 先设置环境变量（可选，不设则用脚本内置默认值）
$env:SUPABASE_EXPORT_URL = "https://xxx/functions/v1/export-students-flat"
$env:SUPABASE_KEY = "your_anon_or_service_role_key"
$env:FEISHU_APP_ID = "cli_xxx"
$env:FEISHU_APP_SECRET = "xxx"
$env:FEISHU_APP_TOKEN = "xxx"
$env:FEISHU_TABLE_ID = "tblxxx"

# 执行（--clear-existing 表示先清空飞书表已有记录再全量写入）
python .\export_students_flat_to_feishu.py --clear-existing
```

> 与 Tab4「飞书全量同步」的区别：Tab4 默认调用的是 `意向学员关系导入到飞书多维表格.py`（同步的是「绑定关系」表），
> 本脚本同步的是「学员平铺数据」（`export-students-flat` 接口），两者是不同的数据源和目标表，不要混用。

## 七、常见问题排查

| 现象 | 排查思路 |
|---|---|
| 双击 exe 无反应/一闪而过 | 大概率是 `_internal` 目录被误删或不完整；重新解压/复制完整目录 |
| `python 导入控制台.py` 报 `ModuleNotFoundError: task_runner` 或 `custom_plugins` | 确认同目录下存在 `task_runner.py` 和 `custom_plugins.py`；若缺失从 `数据结构处理/意向学员绑定关系查询系统/` 复制 |
| contact.db 同步/定时拷贝一直失败 | 检查「来源根目录」网络路径是否可访问（如 `X:\chatlog_backup` 盘符是否已映射），以及「目录前缀」是否匹配实际备份目录名 |
| 飞书全量同步后表内数据消失 | 检查是不是在未勾选 Dry Run 的情况下执行了「立即执行一次」但上游接口返回异常（清空后写入失败）；查看日志中的错误堆栈，必要时重新执行一次全量同步 |
| 用户上传显示大量 skipped | 秒哒 `import-users` 对已存在账号默认计入 skipped，不会覆盖，属于正常行为；如需更新密码，走 GUI 或脚本正常流程即可（密码不同会自动判定为需要更新） |
| 中文文件名在某些终端里显示乱码 | 属于终端编码显示问题，不影响实际文件，用文件资源管理器或 `chcp 65001` 后的 PowerShell 查看即可 |

## 八、注意事项

1. **密钥安全**：各脚本顶部硬编码了 Supabase / 飞书的 `anon_key`、`app_secret` 等凭证，仅限内部使用，**不要把本目录任何脚本或截图对外发布**。
2. **飞书全量同步是破坏性操作**：正式执行前务必先用 Dry Run 确认统计数字正常。
3. **改脚本不用重新打包 exe**：`内部备注导入.py`、`意向学员关系导入到飞书多维表格.py`、`上传用户结构.py`、`定时拷贝任务.py` 以及所有「扩展功能」插件脚本，都是通过界面里「外置脚本路径」动态加载执行的，**改完保存即可生效**，不需要重新生成 exe。只有改 `导入控制台.py` 本身（界面结构、Tab 布局等）才需要重新打包。
4. **`_internal` 目录不要动**：这是 PyInstaller 打包产物，删除或移动会导致 exe 无法启动。
